updated: 2026-11-10T23:33

- (event) Create: input = final PRD prd-Chhaap-2026-11-10 (synced with architecture in #9) + addendum; spine architecture-Chhaap-2026-11-10 adopted as companion (AD-1..AD-12 stable); rich input, direct extraction, no elicitation; slug Chhaap inherited
- (decision) Why: pain + mandate-free vision: Bitly's generator outages block the 4-person Davi Codes team (Kenya, 2 clients); want on-brand dynamic codes on infrastructure they control at near-zero cost
- (capability) CAP-1 (FR-1) intent: an allowlisted team member signs in with Google; success: allowlisted account reaches app, other accounts see 'not authorised' and read/write nothing, no other providers
- (capability) CAP-2 (FR-2) intent: owner adds/removes team emails; success: added email signs in at once, removed email refused on next request, non-owners can't see list, owner can't remove self
- (capability) CAP-3 (FR-3) intent: team creates and renames clients; success: case-insensitive duplicate name refused, client has a preset before any code, clients can't be deleted
- (capability) CAP-4 (FR-4) intent: team edits a client's preset and it applies to all that client's codes; success: save re-checks every non-archived code and is refused listing failures if any fails, each save in preset history, restore re-checks
- (capability) CAP-5 (FR-5) intent: team attaches an optional PNG/SVG logo to a preset; success: other formats refused, >30% bounding box warns without blocking, logo embedded in exports
- (capability) CAP-6 (FR-6) intent: team creates a code from client + http(s) destination + name; success: invalid URL/no name refused, random slug, saved only after passing scan check, up to 3 silent fresh-slug retries, nothing saved on failure
- (capability) CAP-7 (FR-7) intent: team changes a code's destination without reprinting; success: scans reach new destination within an hour, immutable change log entry (who/when/old/new), no re-check
- (capability) CAP-8 (FR-8) intent: team renames a code; success: name changes, rename not in change log
- (capability) CAP-9 (FR-9) intent: team pauses, archives, reactivates codes; success: inactive page within an hour, warning before pause/archive, unarchive re-checks and stays archived on fail, status changes logged, no deletion
- (capability) CAP-10 (FR-10) intent: anyone scanning reaches the active code's destination; success: active -> destination, paused/archived -> inactive page not naming client, unknown slug -> not-found, no sign-in needed
- (capability) CAP-11 (FR-11) intent: team sees how often each code is scanned; success: library shows 'at least N', monitor requests uncounted, counting failure never blocks redirect
- (capability) CAP-12 (FR-12) intent: system proves a drawn code reads back as its short link whenever something changes; success: pass only if decodes exactly at 2000 px and 160 px, runs only on create / preset save / leaving archive, no override
- (capability) CAP-13 (FR-13) intent: team finds a client's code by name; success: list shows name, preview, destination, status, scan count, creator, created date; partial case-insensitive search; archived hidden unless asked
- (capability) CAP-14 (FR-14) intent: team downloads a print-ready PDF or PNG of a passed code; success: A4 vector PDF centred, PNG >=2000 px, 4-module quiet zone, current preset with embedded logo, only codes whose stored pass matches current preset and library versions
- (capability) CAP-15 (OPS-2) intent: owner learns when the redirect is down; success: external check on a dedicated uncounted monitoring path on chhaap.link emails owner on failure, never uses a client code
- (capability) CAP-16 (OPS-4) intent: data can be restored after accidental deletion; success: clients, presets, codes, logs and logos exported on a schedule to separate storage and a restore is demonstrated
- (constraint) NFR-1: all data access only for signed-in team members, enforced server-side; redirect is the only public surface
- (constraint) NFR-2: redirect depends only on Davi Codes' Firebase project and chhaap.link, never a third-party QR/link service
- (constraint) Codes store no style; always drawn from the client's current preset (owner rejected freezing style per code)
- (constraint) Short links never change and slugs are never reused: codes and clients are never deleted
- (constraint) NFR-3: cached redirect <500 ms; destination/status changes reach scanners within an hour
- (constraint) NFR-4: create + check a code <10 s; preset re-check <30 s at ~a dozen codes per client
- (constraint) NFR-5: running cost within Firebase free usage on the Blaze plan, ~$5/month budget alert
- (constraint) NFR-6: existing npm packages and Firebase services do the heavy lifting; every new dependency named in the architecture
- (constraint) NFR-7: v1 data model allows v2 client users scoped to their own client's codes, and more than one preset per client, without migration
- (constraint) NFR-8: desktop browsers only (current Chrome, Safari, Firefox, Edge)
- (constraint) A code that fails the scan check can never be downloaded (no override); scannability beats brand fidelity
- (decision) Non-goals: client portal (v2), Bitly migration, non-URL content, multiple presets or per-code overrides, detailed analytics, formats beyond PDF/PNG incl CMYK, custom slugs, deletion, extra roles, general QR SaaS, offering outside Davi Codes, freezing a code's style
- (decision) Success signal: from launch every new code is made in Chhaap; reprint <1 min and new print-ready code <2 min in timed walkthroughs; no printer/client reports an off-brand or unscannable Chhaap code
- (assumption) FR-2 removal effective next request; FR-3 clients undeletable; FR-11 paused/archived scans counted, no bot filtering; FR-12 up to 3 slug retries; FR-14 file name = client + code name; NFR-3/4 targets unmeasured; NFR-8 desktop suffices; OPS-4 weekly; team and scanners in Kenya
